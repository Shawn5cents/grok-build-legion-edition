# 0.2.120 — 2026-08-06

## Features

- The MIXED multi-family DAG preset is validated end to end: MiniMax M3 plans and
  implements, GPT-5.6 Luna architects, and Qwen3 Flash verifies, so the verifier
  never shares a model family with the implementor.
- Subagents that hard-fail on a structured-output request now switch once to
  their configured fallback model instead of ending the run with a provider
  error.
- Models can declare `supports_structured_output = false`, which routes them
  through the StructuredOutput tool path instead of a native `response_format`
  request that the provider would reject.
- The DAG health watcher (`dag-watch`) and the preset smoke checker ship to all
  users rather than living only in a local setup.

## Bug Fixes

- **DeepSeek verifiers** no longer stall the DAG with `response_format type is
  unavailable`; that failure is now treated as fallback-worthy.
- **Qwen structured output** wrapped in a single-element array is unwrapped to
  the expected object before schema validation.
- **MiniMax responses** that omit `created` or `prompt_tokens` now deserialize
  instead of failing the whole turn.
- **`gpt-5.6-luna`** uses `api_backend = "responses"` in every preset, which is
  the only backend where its tool calls work.
- **`minimax-m3`** is marked as not supporting structured output, preventing a
  provider HTTP 400 on every schema request.
- **Per-model config overrides** now honor `supports_structured_output`; the
  field was previously parsed and silently discarded.
- **The FULL preset verifier** is `grok-4.5`, which handles schemas natively.
- **The reported version** matches the source tree again. Earlier commits
  claimed 0.2.120 while the crate manifests still said 0.2.119, so the built
  binary printed a stale version.

## Notes

- Preset changes still require a TUI restart. Configuration binds once at
  session start, so `~/.grok/dag-mode` can name a preset the running process is
  not using yet.
- Fallback is one-shot per child session. A model known to fail is retried by
  each newly spawned subagent; there is no shared cache across spawns.
- Agent-level detail — commit lineage, closed and open fix tickets, the code
  map, and the build/install gotcha — is in `docs/v0.2.120.md`.
