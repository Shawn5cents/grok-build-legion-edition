## Important history note

Three details routinely confuse agents reading this branch. All three are
expected, and none of them indicate a broken release.

1. Commit `a423889` has a commit message that claims "v0.2.120", but it did not
   change any version numbers. Every crate manifest still said `0.2.119` after
   that commit. The real version stamp landed later, in `6daffbd`, as fix ticket
   FT-005.
2. The branch is named `dag-fixes-v0.2.119` even though its tip is stamped
   0.2.120. The branch name was never renamed; it reflects the version that was
   current when the branch was created, not the version it ships.
3. The content of 0.2.120 is the range `a423889..6daffbd` — eight commits — not
   the version bump alone. Reviewing only `6daffbd` shows four one-line manifest
   edits and `Cargo.lock`, which is why this document exists.

## Fix tickets CLOSED in 0.2.120

### FT-001 — Verifier died on `response_format type is unavailable`

DeepSeek rejects native `json_schema` response formats with an HTTP 400. The
verifier subagent surfaced that as a hard failure and the whole DAG stalled.
The error is now classified as fallback-worthy, and a structured-output failure
is detected even when the child returns a non-error but schema-less result.

Key files:
- `crates/codegen/xai-grok-shell/src/agent/subagent/mod.rs`
  (`is_fallback_worthy_prompt_error`, `is_structured_output_failure`)
- `crates/codegen/xai-grok-shell/src/agent/subagent/handle_request.rs`

### FT-002 — Qwen returned an array-wrapped schema object

Qwen wraps structured output in a single-element array instead of returning the
object directly, which failed schema validation. `normalize_structured_output_shape`
now unwraps a one-element array into the object before validation.

Key file:
- `crates/codegen/xai-grok-shell/src/session/acp_session_impl/turn.rs`

### FT-003 — MiniMax responses missing `created` / `prompt_tokens`

MiniMax omits fields the deserializer treated as required, so every MiniMax
response failed to parse. The affected fields now carry `#[serde(default)]`,
and regression tests cover the omitted-field payload shapes.

Key file:
- `crates/codegen/xai-grok-sampling-types/src/types.rs`

### FT-004 — `gpt-5.6-luna` tool calls required the responses backend

Luna only exposes tools through the responses API. All presets now pin
`api_backend = "responses"` for that model.

Key files:
- `tools/dag-presets/full-dag.toml`
- `tools/dag-presets/mixed-dag.toml`
- `tools/dag-presets/economy-dag.toml`

### FT-005 — Version stamp lag

Crate manifests stayed at `0.2.119` while commit messages claimed 0.2.120, so
the built binary reported the wrong version. All four manifests were bumped and
the installed `version.json` was updated. See "Version stamp files" below.

### FT-008 — `supports_structured_output = false` on `minimax-m3`

MiniMax rejects native `json_schema` response formats. Declaring the model as
not supporting structured output routes it through the StructuredOutput tool
path instead of producing a provider 400. The DeepSeek model entries were also
made explicit about their backend and structured-output capability.

### FT-009 — `ConfigModelOverride` dropped `supports_structured_output`

The override struct had no field for `supports_structured_output`, so
`serde_ignored` silently discarded it from user config. Any per-model override
that tried to disable structured output had no effect. The field was added, the
`apply()` path now propagates it, and parse tests cover it.

Key files:
- `crates/codegen/xai-grok-shell/src/agent/config.rs`
- `crates/codegen/xai-grok-shell/src/agent/config_model_override_parse.rs`

## Still OPEN — not in 0.2.120 scope

These were identified during the same investigation but are **not fixed** in
this release. Do not assume they work.

| Ticket | Description | Why it is still open |
|---|---|---|
| FT-006 | Preset switch requires a TUI restart | Config binds once at process start. `~/.grok/dag-mode` and `config.toml` on disk can say `mixed` while the running process is still serving `full`. The disk label can lie until restart. Fixing it requires runtime model rebinding. |
| FT-007 | Cross-spawn sticky fallback cache | Fallback is one-shot per child session only. When a primary model is known-bad, every new subagent spawn re-attempts it and re-pays the failure before falling back. There is no shared, process-wide record of a model that has already failed. |

## Build and install gotcha

This is the single most common mistake when reproducing this release. The
package `xai-grok-pager` is a library; building it does not produce the shipped
binary, so the installed binary keeps reporting the old version string and the
release looks like it failed.

```sh
# WRONG — builds the library only; leaves a stale binary version string
cargo build --release -p xai-grok-pager

# RIGHT — produces the target binary that reports 0.2.120
cargo build --release -p xai-grok-pager-bin --bin xai-grok-pager
cp target/release/xai-grok-pager ~/.local/bin/xai-grok-pager
```

The version string is baked at build time by
`crates/codegen/xai-grok-pager-bin/build.rs` as
`{CARGO_PKG_VERSION} ({git short SHA})`. Because the short SHA comes from `git
rev-parse --short HEAD` during the build, a binary built at a different commit
will print a different SHA even at the same version number.

## How to verify a live install is 0.2.120

```sh
~/.local/bin/xai-grok-pager --version   # must contain 0.2.120
cat ~/.grok/version.json
grep '^version' crates/codegen/xai-grok-*/Cargo.toml
```

Expected results:

- The binary prints `grok 0.2.120 (6daffbd) [stable]`.
- `~/.grok/version.json` reports `"version": "0.2.120"` and
  `"stable_version": "0.2.120"`.
- All four crate manifests listed above report `version = "0.2.120"`.

If the binary prints an older version while the manifests say 0.2.120, the build
used the library package instead of the binary package. Rebuild using the
"RIGHT" command above.

To check which DAG preset is actually active, run `dag status` or read
`~/.grok/dag-mode`. Because FT-006 is still open, treat the running TUI as
authoritative only if it was started after the most recent preset switch.
